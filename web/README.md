# D Deal Inspector & Interior — เว็บไซต์ (frontend)

เว็บไซต์ marketing สำหรับ D Deal Inspector & Interior — บริการตรวจบ้าน/คอนโดก่อนโอนโดยวิศวกรโยธาที่มีใบอนุญาต
และบริการตกแต่ง 9 รายการ เป็นงาน **frontend อย่างเดียว** ไม่มี backend ไม่มี CMS ไม่มีฟอร์ม
ทุก conversion วิ่งออกไปที่ LINE OA กับเบอร์โทร

## Stack

| | |
|---|---|
| Framework | Next.js 16.3.5 (App Router, Turbopack) |
| ภาษา | TypeScript |
| Styling | Tailwind CSS v4 — token อยู่ใน `@theme` block ที่ `src/app/globals.css` |
| Content | MDX ผ่าน `@next/mdx` |
| Font | Noto Sans Thai (ทั้งหัวข้อและเนื้อความ) + Cormorant Garamond (เฉพาะตัวเลขละติน) ผ่าน `next/font/google` |
| Deploy target | static / Vercel — ทุก route เป็น prerendered |

ไม่มี component library, ไม่มี animation library, ไม่มี state management — component ทั้งหมดเขียนเองใน `src/components/`

## รันโปรเจกต์

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # production build
npm run lint
```

ไม่ต้องใช้ environment variable ใด ๆ

### แก้ข้อมูลธุรกิจ

`src/lib/site.ts` เป็น source of truth เดียว — ราคา เบอร์โทร ที่อยู่ เวลาทำการ ลิงก์ LINE
รายการบริการ timeline ตัวเลข stat แก้ไฟล์นี้ไฟล์เดียวแล้วเปลี่ยนทั้งเว็บ

### เพิ่มบทความ

1. วางไฟล์ `.mdx` ใหม่ใน `src/content/articles/`
2. เพิ่ม entry ใน `articles` ที่ `src/lib/articles.ts` (slug ต้องตรงกับชื่อไฟล์)
3. วางภาพปกใน `public/images/` แล้วใส่ชื่อไฟล์ที่ field `image` ของ entry นั้น

หน้ารายละเอียดบทความ (header, CTA, บทความที่เกี่ยวข้อง) มาจาก `src/app/articles/[slug]/page.tsx`
ไม่ต้องแตะเวลาเพิ่มบทความ

## สถาปัตยกรรมข้อมูล — เว็บ information ไม่ใช่ landing page

> การ์ด WMMT-1599 ระบุ **4 หน้า** (หน้าแรก / บริการ / บทความ / ติดต่อเรา) และตั้งเป้า SEO ไว้
> เว็บรอบก่อนหน้าไม่ตรงข้อนี้ เพราะเนื้อหาเกือบทั้งหมดกองอยู่ในหน้าแรกหน้าเดียว

**กฎข้อเดียวที่ต้องจำ: ทุกหัวข้อที่คนถามหาได้ ต้องมี URL ของตัวเอง**
ถ้าส่งลิงก์ให้ใครแล้วต้องบอกว่า "เลื่อนลงไปประมาณครึ่งหน้า" แปลว่าหัวข้อนั้นวางผิดที่

หน้าแรกทำหน้าที่ **บอกว่าเราคือใคร แล้วพาไปหน้าที่ตอบคำถาม** — ไม่ใช่เล่าทุกเรื่องจบในหน้าเดียว
เนื้อหาที่ย้ายออกจากหน้าแรก **ไม่ได้ถูกลบ** ไปอยู่หน้าที่มันเป็นหัวข้อหลักจริง ๆ:

| เนื้อหา | เดิม | ตอนนี้ |
|---|---|---|
| ทำไมต้องตรวจ · ขั้นตอน · ตัวอย่างรายงาน · จุดแข็ง · ตารางราคา · เครื่องมือ | หน้าแรก | `/services/inspection` |
| แกลเลอรีผลงาน | หน้าแรก (`/#gallery`) | `/services/inspection#gallery` — ดู "สองข้อที่ต่างจากแผน" |
| บทความแบบนิตยสาร (ภาพใหญ่ + คำโปรย) | หน้าแรก ~900px | เหลือ **สารบัญ 3 บรรทัด** บนหน้าแรก · ตัวเต็มอยู่ `/articles` |
| รีวิวลูกค้า · ใบอนุญาต กว. · cross-sell ฝั่งตกแต่ง | หน้าแรก | **อยู่หน้าแรกเหมือนเดิม** — การ์ดสั่งไว้ตรง ๆ ว่า Inspection นำด้วยความน่าเชื่อถือ + แตะ Interior |

วัดผลที่ 1280×900 (`document.documentElement.scrollHeight`):

| route | ก่อน | หลัง | section |
|---|---|---|---|
| `/` | 14,562px (16.2 จอ) | **6,919px (7.7 จอ)** | 14 → 8 |
| `/services/inspection` | ~4,000px | **13,841px** | → 14 |
| `/services` · `/services/interior` · `/articles` · `/contact` | — | ไม่เปลี่ยน | — |

สัดส่วนคำของหน้าแรกเทียบทั้งเว็บลดจาก **44% → 19%** · `/services/inspection` ขึ้นมาถือ 46%
ซึ่งเป็นเรื่องปกติของเว็บที่ขายบริการเดียวเป็นหลัก ต่างจากของเดิมตรงที่เนื้อหาชุดนี้
**มี URL · มี 14 anchor · มีสารบัญในหน้า · อยู่ใน `sitemap.ts`**

**สารบัญในหน้า (TOC strip)** — `/services/inspection` มีแถบชิปลิงก์ใต้ hero ทันที
ใช้มาร์กอัปชุดเดียวกับหน้า `/services/interior` ที่มีอยู่ก่อนแล้ว · มีไว้เพื่อไม่ให้หน้ายาว 13,841px
กลายเป็น "landing page ที่แค่ย้ายที่อยู่" — คนที่มาหาราคาต้องกดถึงราคาได้ในคลิกเดียว

> **ทุก anchor ต้องมี `scroll-mt-24`** — `globals.css` ตั้ง `scroll-padding-top: 5.5rem` (88px)
> ให้ `html` อยู่แล้ว เพราะแถบเมนูเป็น `sticky` · ระยะรวมของเว็บนี้คือ **88 + 96 = 184px**
> ถ้า section ใหม่ลืมใส่ `scroll-mt-24` มันจะหยุดสูงกว่าเพื่อน 96px ซึ่งเห็นได้ทันที
> เวลากดไล่ชิปในสารบัญ (`#process` `#gallery` `#about` `#reviews` เคยตกหล่นมาแล้วทั้งสี่ตัว)

### เมนู — 4 หน้าตามการ์ด และไม่มี `#anchor` สักตัว

`navItems` ใน `site-header.tsx` เป็น **source of truth เดียว** ของทั้งแถบบนและเมนูมือถือ
(เมื่อก่อนสองที่นี้ถือคนละรายการกัน แก้ทีต้องแก้สองจุดแล้วหลุดบ่อย)

```
หน้าแรก    → /
บริการ     → /services      ├ บริการทั้งหมด   → /services
                            ├ ตรวจบ้าน-คอนโด → /services/inspection
                            └ งานตกแต่ง      → /services/interior
บทความ     → /articles
ติดต่อเรา  → /contact
```

**กฎ: ปลายทางในเมนูต้องเป็นหน้า ห้ามเป็น `#section`** — ลูกค้าสั่งตรง ๆ ว่ากดเมนูแล้วต้องเข้าหน้านั้น
ไม่ใช่เด้งไป section แบบ landing page · ของเดิมเคยมี 8 รายการโดย 5 ตัวเป็น anchor ของหน้าแรก
(`#process` `#pricing` `#gallery` `#about` `#reviews`) · รอบ IA เหลือ anchor ตัวสุดท้ายคือ "ราคา"
ที่ชี้ `/services/inspection#pricing` ซึ่งยังผิดกฎข้อนี้อยู่ดี **ตอนนี้ตัดออกหมดแล้ว — เหลือ 0**
บริการรายตัว 14 รายการที่เคยลงไว้ในเมนูมือถือแบบ `#slug` ก็ถอดออกด้วยเหตุผลเดียวกัน
ยังเข้าถึงได้จาก `/services` และจากสารบัญในแต่ละหน้าบริการ

ของที่ต้องรู้ถ้าจะแก้เมนู:

- **`<nav>` ต้อง `lg:self-stretch` และ `<li>` ต้อง `h-full`** — เมนูย่อยวาง `top-full` ของ `li`
  ถ้า `li` สูงแค่ 44px ในแถบสูง 96px แผงจะไปโผล่กลางแถบ และมีร่องให้เมาส์หลุดระหว่างทาง
- **แผงย่อยเปิดด้วย `group-hover` + `group-focus-within` ล้วน ไม่มี state** — ไม่มีอะไรต้องจำ
  คนที่ไล่ด้วยคีย์บอร์ดโฟกัสถึง "บริการ" แล้วแผงกางเอง · ตอนซ่อนใช้ `invisible`
  ไม่ใช่ `opacity-0` เฉย ๆ ไม่งั้นแผงที่มองไม่เห็นจะยังกินคลิกอยู่
- **`aria-current="page"` มีได้ตัวเดียวในเมนู** — รายการที่มีเมนูย่อยเป็นหัวกลุ่ม ปล่อยให้ลูกถือป้ายนี้
  ไม่งั้นตอนอยู่ `/services` ทั้ง "บริการ" และ "บริการทั้งหมด" จะประกาศว่าเป็นหน้าปัจจุบันพร้อมกัน
- **สถานะ "อยู่หน้านี้" ใช้เส้นใต้ค้าง ไม่ใช่เปลี่ยนสี** — hover = ตัวหนังสือทอง + เส้นทอง ·
  active = เส้นทองค้าง ตัวหนังสือยังเป็นหมึก · แยกออกว่าอันไหน "อยู่ตรงนี้" อันไหนแค่ "กดได้"
  · **ห้ามเขียน `after:scale-x-0` กับ `after:scale-x-100` ไว้ในสตริงเดียวกัน** Tailwind
  ตัดสิน utility ที่ชนกันด้วยลำดับใน stylesheet ไม่ใช่ลำดับใน class attribute

### สองข้อที่ต่างจากแผนที่ประกาศไว้

- **แกลเลอรีไปอยู่ `/services/inspection` ไม่ใช่ `/services/interior`** — แผนเดิมอิงบรรทัดในการ์ดที่ว่า
  "Interior นำด้วยภาพผลงาน" แต่พออ่าน `gallery` ใน `lib/site.ts` จริงพบว่าทั้ง 9 ภาพเป็นงานตรวจล้วน
  (หมวด บ้าน / คอนโด / Defect / Report และคำบรรยายทุกภาพขึ้นต้นด้วย "ตรวจ…")
  ย้ายไปฝั่งตกแต่งจะกลายเป็นการกล่าวอ้างผลงานผิดประเภท · หน้า `/services/interior`
  นำด้วยภาพอยู่แล้วโดยมีภาพประจำบริการทั้ง 9 รายการ
- **บทความยังอยู่บนหน้าแรก** — แผนเดิมจะตัดทิ้ง แต่พอตัดแล้วเนื้อหาหน้าแรกลิงก์ออกแค่ 3 หน้า
  จาก 4 หน้าที่การ์ดระบุ (ไม่มีทางไป `/articles` นอกจากเมนูบน) จึงทำใหม่เป็น **สารบัญ 3 บรรทัด**
  หัวเรื่อง + metadata เท่านั้น ไม่มีภาพไม่มีคำโปรย · สูง 605px แทนบล็อกเดิม ~900px

## Design token

token ทั้งหมดประกาศใน `@theme` ที่ `globals.css` — ห้าม hardcode สีในคอมโพเนนต์

| token | ค่า | หน้าที่ |
|---|---|---|
| `ink` | `#16355a` | ตัวหนังสือหลัก + พื้นเข้ม + พื้นปุ่มหลัก |
| `ink-deep` | `#0f2742` | สถานะ hover ของปุ่มพื้นกรมท่าเท่านั้น |
| `ink2` / `ink3` | `#4f6274` / `#5c6e7f` | เนื้อความรอง / ข้อความประกอบ |
| `paper` / `warm` / `line` | `#ffffff` / `#f7f3ea` / `#e8e2d6` | พื้น, พื้นสลับ section, เส้นคั่น |
| `gold-500` | `#b07f32` | เน้นเฉพาะ **ตัวใหญ่กับกราฟิก** — คำเน้นในหัวข้อ ตัวเลขสถิติ ไอคอน ขอบเหรียญ วงโฟกัส |
| `gold-700` | `#8f6420` | เน้นกับ **ตัวหนังสือขนาดปกติ** — ป้ายกำกับ ลิงก์ ราคา เลขลำดับขั้นตอน |
| `line-green` | `#06c755` | สีแบรนด์ LINE **ห้ามแก้** เป็นข้อกำหนดของ LINE เอง |

**ทั้งเว็บมีสีจริงแค่สองสี** (กรมท่า + ทองอำพัน) บนพื้นขาว/ครีม เดิมเคยแยกสีตามฝั่งบริการ
(น้ำเงิน = ตรวจสอบ, ส้ม = ตกแต่ง) แต่ยุบเหลือสองสีแล้ว — ฝั่งบริการแยกกันที่ **ภาพกับถ้อยคำ** ไม่ใช่สี
สองแบรนด์สองสีบนเว็บเดียวทำให้ไม่มีสีไหนเป็นสีของแบรนด์เลย

สองสีนี้ **แบ่งหน้าที่กันชัดเจนและห้ามสลับ**:

- **กรมท่าคือ "โครง"** — หัวข้อ พื้นปุ่ม พื้น section เข้ม
- **ทองคือ "เสียงเน้น"** — ป้ายกำกับ คำเน้นในหัวข้อ ตัวเลข ไอคอน

ห้ามทำปุ่มพื้นทองตัวหนังสือขาว — **ไม่ผ่านคอนทราสต์ไม่ว่าจะเลือกเฉดทองไหน** (ทองที่เข้มพอให้ขาวอ่านได้
จะมืดจนไม่เหลือความเป็นทอง) พื้นเข้มใช้ `ink` เสมอ และห้ามใช้ทองเป็นพื้นเต็ม section

คอนทราสต์ที่ตรวจแล้ว (WCAG AA ต้องการ 4.5:1 ตัวปกติ / 3:1 ตัวใหญ่ ≥24px หรือ ≥18.66px ตัวหนา และกราฟิก):

| คู่สี | อัตรา |
|---|---|
| `ink` บน paper / warm | 12.42 / 11.21 |
| ขาวบน `ink` | 12.42 |
| `ink2` บน warm / paper | 5.69 / 6.30 |
| `ink3` บน warm / paper | 4.75 / 5.26 |
| `gold-700` บน warm / paper | 4.73 / 5.23 |
| `gold-500` บน warm / paper / `ink` | 3.20 / 3.54 / 3.51 |

**วัดบนพื้น `warm` เสมอ** ครีมเป็นพื้นที่ยากกว่าขาวทุกกรณี ค่าที่ผ่านบนขาวอาจตกบนครีม
เฉดที่ลองแล้วตก: `#C08A3C` (2.73 บน warm), `#96681c` (4.42), `#65788a` (4.12)

`gold-500` เป็นค่าเดียวที่ผ่าน 3:1 **ครบทั้งขาว ครีม และกรมท่า** จึงใช้เป็นวงโฟกัสสีเดียวได้ทั้งเว็บ
โดยไม่ต้องสลับตามพื้นหลัง — ถ้าจะเปลี่ยนเฉดทองต้องวัดครบทั้งสามพื้น

> `gold-700` วัดไว้เฉพาะบนขาวกับครีม **ห้ามเอาไปวางบนพื้น `ink`** · ตอนนี้ไม่มีทองอยู่บนพื้นเข้มเลย
> สักจุด (ตรวจแล้วที่ `VerifyLicense`, `ContactCta`, FAB, footer) — บนพื้นเข้มใช้ขาวหรือ `white/70` แทน

### Typography

- ภาษาไทยทั้งหมดใช้ **Noto Sans Thai** ตามที่ลูกค้ากำหนด — ทั้งหัวข้อและเนื้อความ
- `--font-display` (Cormorant Garamond, โหลดเฉพาะ subset latin) **ใช้กับตัวเลขละตินเท่านั้น** —
  เลขลำดับขั้นตอน, ตัวเลขสถิติ, เลข `404`, เลขใบอนุญาต, เครื่องหมายคำพูดเปิดในรีวิว
  ห้ามเอาไปครอบข้อความไทยเด็ดขาด
- **สัญลักษณ์ `฿` (U+0E3F) ห้ามอยู่ใน `font-display`** — Cormorant ไม่มี glyph นี้ (Google Fonts
  ไม่มี subset ไทยให้ด้วย) เบราว์เซอร์จึงหยิบ fallback แบบ metric-adjusted มาวาด ได้สัญลักษณ์
  ซานส์หนาทึบยืนติดเลขเซริฟบาง ๆ อ่านเป็นความผิดพลาด · ที่ตารางราคาจึงสั่งให้ `฿` เป็น `font-head`
  ขนาด `0.58em` น้ำหนักปกติ — พอคนละแบบ**ชัดเจน**มันจะอ่านเป็น "หน่วยเงินนำหน้าจำนวน"
  เหมือนตาราง spec ที่เขียนหน่วยเล็กกว่าค่า แทนที่จะอ่านเป็นฟอนต์หลุด
- `body` ตั้ง `line-height: 1.75`, หัวข้อ 1.35, `h1` 1.22 — ภาษาไทยมีสระบน-ล่าง
  ถ้าใช้ leading แบบ Latin สระจะชนกัน
- **พื้นล่างของ line-height ข้อความไทยคือ 1.5** ต่ำกว่านั้นสระบน (ิ ี ึ ื ั) กับวรรณยุกต์
  ของบรรทัดล่างจะเบียดกันจนอ่านผิดบรรทัด · ค่าที่ Tailwind ให้มากับ `text-sm` (1.429)
  และ `text-xs` (1.333) คิดมาสำหรับภาษาละติน **ต่ำกว่าพื้นทั้งคู่** จึง override ที่ `@theme`
  ผ่าน `--text-sm--line-height` / `--text-xs--line-height` เป็น 24px / 20px
  (ไล่ขั้นละ 4px ต่อจาก body 16/28 · ยังอยู่บนกริด 4pt) — แก้ที่เดียวแทนการไล่เติม
  `leading-` ราย element ~30 จุด เพราะคนที่เขียน `text-sm` ครั้งต่อไปจะพลาดซ้ำ
  · utility `leading-*` ยังทับได้ตามปกติ เลขละตินที่ตั้งใจให้ `leading-none` จึงไม่โดนผลกระทบ
- หัวข้อทุกระดับตั้ง `letter-spacing: normal` — **ห้ามใส่ tracking ติดลบกับภาษาไทย**
  สระบนกับวรรณยุกต์จะเกยพยัญชนะตัวถัดไป

> ⚠️ **ห้ามถ่าง `letter-spacing` กับภาษาไทย ไม่ว่าบวกหรือลบ** — ไทยไม่เว้นวรรคระหว่างคำ
> ถ่างแล้วทั้งตาแยกขอบเขตคำไม่ออก และสระ/วรรณยุกต์หลุดจากพยัญชนะ
> คอมโพเนนต์ที่ถ่าง `0.1em` ขึ้นไป (`TechLabel` `IndexLabel` `ImageMarker` `Eyebrow variant="rule"`)
> จึง **รับเฉพาะข้อความอังกฤษหรือตัวเลข** ถ้าข้อมูลเป็นไทยให้ใช้ `text-sm text-ink3` ธรรมดาแทน
>
> เช็กทั้งเว็บด้วยการรันใน console: หา leaf element ที่มีอักษรไทยแล้ว `letterSpacing / fontSize >= 0.05`
> ควรได้ 0 ทุกหน้า (เคยหลุดมาแล้ว 3 จุด: meta ของบริการ, เวลาทำการใน CTA ปิดท้าย, แท็กหมวดบทความ)

### Elevation

เหลือ **2 ระดับ และทั้งคู่จางมาก** อย่าเขียน `shadow-[...]` เฉพาะจุดเพิ่ม

| token | ใช้กับ |
|---|---|
| `shadow-card` | เงาบาง ๆ ของการ์ดที่อยู่นิ่ง |
| `shadow-lift` | ปุ่มลอย (FAB) เท่านั้น |

งานพรีเมียมแยกชั้นด้วย **เส้นบาง + ที่ว่าง** ไม่ใช่เงาฟุ้ง — ถ้าเห็นเงาชัดแปลว่าใส่หนักเกินไปแล้ว
`shadow-cta` (เงาสีแบรนด์) ถูกถอดออกทั้งหมดในรอบ editorial

เงาทั้งสองผสม **กรมท่า ไม่ใช่ดำ** (`rgb(22 53 90 / …)`) — ดำล้วนบนพื้นครีมจะออกเทาสกปรก

### ลายเซ็นงานออกแบบ (CI)

ทิศทางปัจจุบันคือ **editorial กรมท่า+ทอง** — สงบ เส้นบาง ที่ว่างเยอะ ภาพนำ
หกอย่างนี้คือสิ่งที่ทำให้ทุกหน้าดูเป็นชุดเดียวกัน

1. **ป้ายกำกับหัวข้อเป็นอังกฤษตัวพิมพ์ใหญ่ มีขีดนำ** — `<Eyebrow>` = ขีดสั้น + ข้อความ
   `tracking-[0.2em]`
   > ที่ต้องเป็นอังกฤษเพราะ tracking กว้างขนาดนี้ใช้กับไทยไม่ได้ (ไทยไม่เว้นวรรคระหว่างคำ
   > ถ้าถ่างเกิน ~0.08em ตาจะแยกขอบเขตคำไม่ออก) — แต่ป้ายกำกับถ่างคือหัวใจของลุค editorial
   > จึงเลือกทางออกว่า **ป้ายกำกับทุกอันเป็นอังกฤษ** ส่วนไทยไปอยู่ที่หัวข้อจริงแทน
   ใช้ `variant="pill"` เฉพาะตอนที่มันเป็น *แท็กหมวดหมู่จริง ๆ* (หมวดบทความ) เท่านั้น ·
   บนพื้นเข้มส่ง `tone="invert"`
2. **radius น้อยและคงที่** — การ์ด/ปุ่ม/ภาพใช้ `rounded-sm` (4px) เกือบทั้งหมด
   มนกว่านี้จะอ่านเป็นแอป/SaaS ทันที ซึ่งตรงข้ามกับงานสถาปัตย์-วิศวกรรม
   **วงกลมทั้งเว็บมีแค่ 2 ที่**: เลขลำดับขั้นตอน กับ avatar รีวิว (ไม่นับ FAB ซึ่งเป็นปุ่มลอย)
   — ถ้ามีมากกว่านี้ลุคจะพัง
3. **hero ภาพชนขอบจอขวา** — ตัวหนังสืออยู่ในคอลัมน์ `lg:w-[46%]` ที่อิงขอบ `Container`
   ส่วนภาพเป็น `lg:absolute lg:inset-y-0 lg:right-0 lg:w-[52%]` **ไม่มี radius ไม่มีเงา**
   มือถือภาพไหลต่อท้ายบล็อกตัวหนังสือแบบเต็มกว้าง · ใช้เหมือนกันทั้งหน้าแรก / ตรวจสอบ / ตกแต่ง
   > **การ์ดคร่อมขอบภาพ** — หน้าแรกมีการ์ดพื้น `ink` ใบเดียวที่ `lg:-left-14` คร่อมขอบซ้ายของภาพ
   > บอกสองอย่างที่คนตัดสินใจจริง ๆ ใช้: "ใครตรวจ" (ใบอนุญาต) กับ "เริ่มที่เท่าไหร่" ·
   > มือถือวางทับ **ในภาพ** (`inset-x-4 bottom-4`) ไม่ให้ล้นออกนอก section
   > · แพตเทิร์นเดียวกันใช้ซ้ำที่ About (การ์ด `INSPECTION TOOLKIT`)
4. **แถบการันตี 4 ช่องใต้ hero** — ไอคอนเส้นสีทอง + ข้อความ ไม่มีวงกลมรองพื้น
   ตอบว่า "ทำไมต้องเชื่อ" ก่อนผู้ใช้เลื่อนลงไปอ่านรายละเอียด
5. **ขั้นตอนเรียงนอนบนจอใหญ่ เรียงตั้งบนมือถือ** — เลขลำดับเป็นเซริฟในวงกลมขอบบาง
   เชื่อกันด้วย **เส้น 1px** ไม่ใช่ลูกศรหรือไอคอน · เส้นเชื่อมต้องไม่ขึ้นที่ขั้นสุดท้าย
   (เรนเดอร์ด้วยเงื่อนไข `i < steps.length - 1` **ไม่ใช่** `last:hidden` — ดูหัวข้อ "คนรับงานต่อ")
6. **ปุ่ม CTA คู่ในแถบเมนู** (เดสก์ท็อปเท่านั้น) — "ขอใบเสนอราคา" เป็นลิงก์ข้อความ
   + "นัดหมายตรวจบ้าน" เป็นปุ่มพื้นกรมท่า · มือถือใช้แถบลอยล่างจอแทน ไม่ต้องมีสองชุด ·
   ลิงก์ซ้ายเคยถูกกั้นไว้ที่ `xl` เพราะเมนู 8 รายการชนปุ่มพอดีที่ 1280px **ตอนเมนูเหลือ 4 รายการ
   ลงมาเป็น `lg` ได้แล้ว** (วัดที่ 1024: ลูกของแถบรวมกัน 721px ในคอนเทนเนอร์ 1024px)
7. **จังหวะ section เดียวกันทั้งเว็บ: `py-24 sm:py-32`** — ทั้งหน้าแรกและหน้าใน
   ไม่มี section ไหนใช้ค่าอื่น (ยกเว้นแถบหัวหน้าใน `py-14 sm:py-20` ซึ่งตั้งใจให้แน่นกว่า
   เพราะเป็นบทนำไม่ใช่เนื้อหา) · ถ้าเพิ่ม section ใหม่ให้ใช้ค่านี้ อย่าตั้งค่าเฉพาะจุด

hero ของหน้าแรก / ตรวจสอบ / ตกแต่ง ใช้พื้น `warm` ทั้งสามหน้า ทำให้ทั้งเว็บไล่เป็น
**ครีม → ขาว → ครีม** สลับกันไป ไม่ต้องใช้เส้นคั่นหนักหรือเงาเพื่อแบ่ง section

> **จังหวะเส้นคั่น — ดูของที่อยู่ติดกันก่อนใส่ border เสมอ**
> บล็อกพื้น `warm` เป็นตัวประกาศเส้นของตัวเอง (`border-y border-line`) เพราะมันต้องมีขอบทั้งบนล่าง
> ถึงจะอ่านเป็นแถบ · บล็อกพื้นขาวที่ตาม warm มาให้ **ไม่ต้องใส่ `border-t`** เพราะ warm
> ข้างบนให้ขอบล่างไว้แล้ว · ถ้าใส่ทั้งคู่จะได้เส้นผม 2 เส้นซ้อนกันห่าง 1px ซึ่งเห็นชัดที่ 2x
> (หน้า `/services/inspection` โดนมาแล้ว 2 จุด — Equipment ถูกลดเหลือ `border-t` อย่างเดียว
> และ section ของ Timeline ถอด border ออกทั้งคู่เพราะ `Gallery` ข้างบนให้มาแล้ว)
> ข้อยกเว้นคือ `VerifyLicense` ซึ่งเป็นก้อน `bg-ink` — มันแบ่งตัวเองด้วยค่าความสว่าง
> section ที่ห่อมันจึงไม่ต้องมีเส้นเลย

### Motion — `<Reveal>` / `<Counter>`

`components/reveal.tsx` เป็น **motion primitive ตัวเดียวของเว็บ** — ค่อย ๆ เผยเนื้อหาตอนเลื่อนถึง
ใช้ `IntersectionObserver` เติม `data-shown` ครั้งเดียวแล้ว `disconnect()`

- **สถานะซ่อนอยู่ใน CSS ไม่ใช่ใน JS** (`[data-reveal]` ใน `globals.css`) — ถ้าตั้ง state เริ่มต้นใน React
  จะมีจังหวะที่เนื้อหาโผล่แล้วหายตอน hydrate
- ไล่ลำดับการ์ดในกริดด้วย prop `delay` — **60–80ms ต่อใบ** มากกว่านี้จะรู้สึกว่าเว็บช้า
- `prefers-reduced-motion: reduce` **ปลดที่ CSS** โดยบังคับทั้ง `opacity` · `transform` · `clip-path`
  > การตัด `transition-duration` อย่างเดียว **ไม่พอ** — element ที่ยังไม่เคยเข้าจอจะค้างที่ `opacity: 0`
  > (หรือโดน clip) ตลอดไป ต้องปลดสถานะซ่อนตรง ๆ ทั้งสามตัว เพราะแต่ละ variant ซ่อนคนละวิธี
  > `[data-progress-line]` ก็ต้องปลดด้วย ไม่งั้นเส้นความคืบหน้าจะค้างที่ `scaleY(0)`
  > ถ้าแก้ CSS ส่วนนี้ให้ทดสอบด้วย reduced-motion เสมอ

**มี 8 ท่า ไม่ใช่ท่าเดียว** — `up` `rise` `fade` `left` `right` `clip` `line` `scale`
ถ้าทุก section เข้าด้วย fade-up เหมือนกันหมด จังหวะการเลื่อนจะซ้ำจนอ่านออกว่าเป็นเทมเพลต
เลือกท่าให้ตรงกับเนื้อหา: ภาพใช้ `clip` (เปิดจากล่างขึ้นบน) · เส้นคั่นใช้ `line` (ลากจากซ้าย)
· รายการใช้ `left`/`right` · สถิติใช้ `rise` · ภาพรายงานใช้ `scale`

> ⚠️ **กับดัก containing block** — element ที่มี `transform` ไม่เท่ากับ `none` จะกลายเป็น containing block
> ของลูกที่เป็น `position: absolute` ทั้งหมด แถวใน `FeaturedServices` จึงถูกล็อกไว้ที่ `variant="fade"`
> (ท่าเดียวที่ไม่มี transform) เพราะภาพคอลัมน์ขวาต้องอิง `<ul>` ไม่ใช่ `<li>` — มีคอมเมนต์กำกับไว้ในไฟล์แล้ว

`<Counter>` นับเลขขึ้นตอนเลื่อนถึง ใช้กับสถิติใน `TrustBar`
ค่าตั้งต้นคือ **ข้อความเต็มเสมอ** ดังนั้น no-JS และ reduced-motion ก็เห็นเลขถูก

> ⚠️ มี `setTimeout` กันเหนียวบังคับให้จบที่ค่าจริง **ห้ามเอาออก** — `requestAnimationFrame` หยุดเดิน
> เมื่อแท็บถูกซ่อน ถ้าผู้ใช้สลับแท็บกลางคัน ตัวเลขจะค้างที่ค่าผิดตลอดไป (เจอจริงตอนทดสอบ: ค้างที่ `18+`
> ทั้งที่ค่าจริงคือ `1,500+`) ซึ่งร้ายแรงกว่าการไม่มีแอนิเมชัน เพราะนี่คือสถิติที่ลูกค้าอ่านเป็นคำกล่าวอ้าง

แถบเมนูหดจาก `lg:h-24` → `lg:h-[4.5rem]` เมื่อ `scrollY > 24` (ไม่ใช่ `> 0` เพื่อไม่ให้หดกลับไปกลับมา
ตอนสะบัดนิ้วเบา ๆ บนมือถือ) พร้อมเปลี่ยนเส้นขอบล่างจากใสเป็น `line` และเพิ่ม `shadow-card`

ปุ่มทั้งเว็บมี 4 โทน ส่งผ่าน prop `tone` เท่านั้น: `primary` / `outline` (บนพื้นสว่าง)
· `onDark` / `outlineDark` (บนพื้น `ink`)

### Utility ที่เขียนเอง

| utility | ทำอะไร |
|---|---|
| `card` | radius 4px + border + พื้นขาว ในคลาสเดียว |
| `placeholder-hatch` | ลายทแยงแทนภาพ ใช้ที่ช่อง Google Maps ที่เดียว |
| `tnum` | `font-variant-numeric: lining-nums tabular-nums` ใส่กับราคา/สถิติทุกจุด — คุมทั้ง *ความกว้าง* (ไม่งั้นคอลัมน์ขยับตอนค่าเปลี่ยน) และ *ความสูง* ของตัวเลข |

`lining-nums` ใน `tnum` จำเป็นเพราะ Cormorant ตั้งต้นเป็นเลขแบบ old-style — `3` กับ `5` ห้อยใต้เส้นบรรทัด
ส่วน `0` สูงแค่ x-height สวยตอนแทรกในย่อหน้า แต่พอเรียงเป็นคอลัมน์ราคาชิดขวา ขอบบนของแต่ละแถวจะกระโดด
ไม่เท่ากันจนต้องอ่านทีละตัวแทนการกวาดตาเทียบ · `tnum` ติดเฉพาะเลขที่มีไว้ให้เทียบกันอยู่แล้ว
จึงคุมทั้งสองเรื่องที่เดียวได้ **อย่าเติม utility `tabular-nums` ของ Tailwind ทับ** — Tailwind ประกอบ property
นี้จากตัวแปร `--tw-*` ผลคือมันจะ *แทนที่* ค่าใน `.tnum` ทั้งก้อน ไม่ใช่รวมกัน แล้ว `lining-nums` จะหาย

การ์ดที่กดได้ทั้งใบใช้คู่กับ `<GhostLink stretch>` หรือ `after:absolute after:inset-0` ที่ลิงก์หลัก —
ตัวการ์ดต้องเป็น `relative` ด้วย · `GhostLink` รับ `className` ได้ แต่ **ส่งได้เฉพาะเรื่อง "วางที่ไหน"**
(margin / grid placement / order) ห้ามส่งสีหรือขนาดตัวอักษรไปทับ เพราะจะแพ้เงียบ ๆ ตามกฎ Tailwind ด้านล่าง

### Inspection Language

ภาษาภาพชุดเล็ก ๆ ที่ยืมมาจากใบรายงานตรวจบ้านจริง — ทำให้หน้าเว็บอ่านเป็น *เอกสารทางเทคนิค*
มากกว่า *หน้าขายของ* **โดยไม่เพิ่มสีหรือฟอนต์ใหม่เลย** อยู่ใน `components/ui.tsx`

| คอมโพเนนต์ | ทำอะไร |
|---|---|
| `TechLabel` | ป้ายเทคนิคเล็ก ถ่างกว้าง เช่น `REFERENCE IMAGES` · `RATE CARD · THB` |
| `IndexLabel` | ตัวนับลำดับแบบแบบก่อสร้าง `01 / 05` + ชื่อกำกับ |
| `DrawnRule` | เส้นคั่นบางที่ลากตัวเองจากซ้ายตอนเลื่อนถึง (`Reveal variant="line"`) · `tone`: `light` พื้นสว่าง · `dark` พื้นเข้ม · `ink` เส้นหนักที่ใช้เป็น "เส้นหัวตาราง" |
| `ImageMarker` | หมุดชี้ตำแหน่งบนภาพ เลียนแบบการวงจุด defect ในรายงาน |

> 🔒 **กฎเหล็ก: ทุกตัวเลขที่โชว์ต้องมาจากข้อมูลที่มีอยู่จริง** — ลำดับรายการ, จำนวนที่นับได้, ปีจากนาฬิกาเครื่อง
> **ห้ามแต่งเลขให้ดูเท่** เลขรายงานจึงเขียนเป็น `DD-XXXX` และเลขใบอนุญาตเป็น `ภย. XXXXX`
> ให้อ่านออกทันทีว่ายังเป็น placeholder ไม่ใช่เลขปลอมที่ดูเหมือนจริง
> ด้วยเหตุผลเดียวกัน รีวิวใช้ `FIELD NOTE 01` แทนดาว ★★★★★ เพราะเว็บนี้ไม่มีระบบให้คะแนนจริงรองรับ

> ⚠️ Tailwind ตัดสิน class ที่ชนกันด้วย **ลำดับใน stylesheet ที่ generate ออกมา ไม่ใช่ลำดับใน `className`**
> เพราะงั้น `MockImage` / `PlaceholderImage` จึงไม่ตั้ง radius เป็นค่าตั้งต้น — ให้ call site ส่งมาเสมอ
> ถ้าตั้งไว้แล้วส่งค่าอื่นมา override อาจไม่ทำงาน (โดนมาแล้ว 2 รอบ)

## ภาพ mock — ต้องเปลี่ยนก่อนขึ้น production

ภาพทั้งเว็บตอนนี้เป็น **stock จาก Unsplash** ไม่ใช่ผลงานจริงของลูกค้า
ใส่ไว้เพื่อให้ลูกค้าเห็นภาพรวมตอน UAT เท่านั้น — **ห้ามขึ้น production ทั้งชุด**
รายการไฟล์กับเครดิตอยู่ใน `public/images/CREDITS.md`

> 🔴 **แกลเลอรีคือจุดที่เสี่ยงที่สุด** — section อื่นใช้ stock เป็น "ภาพประกอบ" ซึ่งคนอ่านเข้าใจได้
> แต่แกลเลอรีอ้างตรง ๆ ว่า **"ตัวอย่างสิ่งที่เราเข้าไปตรวจ"** ภาพ stock ตรงนี้จึงเป็นการกล่าวอ้างเท็จ
> ต่อผู้บริโภค ไม่ใช่แค่ placeholder · ทีมแจ้งความเสี่ยงนี้แล้วและ**ลูกค้ายืนยันให้ทำด้วย stock ไปก่อน**
> เพื่อดู layout ตอน UAT · **ต้องเปลี่ยนเป็นภาพหน้างานจริงก่อนขึ้น production เท่านั้น**

> ภาพแกลเลอรี 9 รูปกับหมวดของมันอยู่ใน `gallery[]` ที่ `lib/site.ts`

ทุกจุดเรียกผ่าน `MockImage` ใน `components/ui.tsx` ซึ่งห่อ `next/image` (`fill` + `object-cover`)

### รอบ editorial — ต่างจาก brief ที่ลูกค้าส่งมาตรงไหน

### รอบ art direction — ยกระดับการนำเสนอ ไม่แตะ CI และไม่แตะเนื้อหา

> ลูกค้าสั่ง **"ห้ามเปลี่ยน CI เดิมของเว็บไซต์"** และ **"อย่าแก้ปัญหา design ด้วยการเปลี่ยนสี"**
> รอบนี้จึงไม่มี token สี ฟอนต์ หรือ copy ตัวไหนเปลี่ยนเลย — เครื่องมือที่ใช้ได้มีแค่
> **layout · typography scale · spacing · composition · image treatment · motion · interaction · detail**
> เป้าหมายคือให้อ่านเป็นงานของดีไซเนอร์ ไม่ใช่งาน AI generate · สัดส่วนที่ตั้งไว้คือ
> **70% professional/technical · 30% premium/editorial**

| เดิม | ตอนนี้ | เหตุผล |
|---|---|---|
| ทุก section เข้าด้วย fade-up ท่าเดียว | **8 ท่า** เลือกตามเนื้อหาของ section | จังหวะการเลื่อนที่ซ้ำกันหมดคือสิ่งที่ทำให้เว็บอ่านออกว่าเป็นเทมเพลต |

| `FeaturedServices` 1 ใบใหญ่ + 3 แถว | **editorial list 4 แถว + คอลัมน์ภาพร่วมที่สลับตาม hover** | แถวที่มีเลข/ชื่อ/คำอธิบาย/ลูกศร อ่านเป็นสารบัญงาน ไม่ใช่กริดการ์ด |

### รอบ information architecture — ย้ายที่อยู่ของเนื้อหา ไม่แตะงานออกแบบ

> ลูกค้าสั่ง **"เว็บนี้ทำเป็นเว็บ information ไม่ใช่ landing page"** + **"ต้องการ mock ข้อมูลไปก่อน"**
> รอบนี้จึง **ไม่มี copy · ตัวเลข · ราคา · รีวิว · ภาพ ตัวไหนเปลี่ยนหรือถูกลบเลย**
> ข้อมูล mock ทั้งชุดยังอยู่ครบเพราะยังต้องเอาไปให้ลูกค้าดูภาพรวม · ที่เปลี่ยนคือ **section ไหนอยู่ URL ไหน**
> component แทบทุกตัวถูกย้ายทั้งก้อนโดยไม่แก้ข้างใน — ดูรายละเอียดและตัวเลขที่วัดได้
> ที่หัวข้อ **"สถาปัตยกรรมข้อมูล"** ด้านบน

| เดิม | ตอนนี้ | เหตุผล |
|---|---|---|
| หน้าแรกสูง 16.2 จอ ถือ 44% ของคำทั้งเว็บ | **7.7 จอ · 19%** | หน้าแรกของเว็บ information คือสารบัญ ไม่ใช่ที่เก็บของ |
| ขั้นตอน / ราคา / แกลเลอรี / เกี่ยวกับ ไม่มี URL | อยู่ใต้ `/services/inspection` มี anchor + สารบัญในหน้า | ส่งลิงก์ให้ลูกค้าได้ · Google เก็บเป็นหน้าได้ |
| `#pricing` เขียนอยู่ในไฟล์หน้าแรก | แยกเป็น **`PricingTable`** ใน `sections.tsx` | ตารางราคาต้องใช้ได้หลายหน้า และห้ามมีสองชุด |
| เมนู 8 รายการ ครึ่งหนึ่งเป็น `/#anchor` | **4 รายการตามการ์ด · anchor เหลือ 0** (บริการสองสายเป็นเมนูย่อย) | anchor ของหน้าแรกพังทันทีที่ section ย้ายบ้าน · และเมนูที่กดแล้วเด้งไป section คือพฤติกรรมของ landing page — ดูหัวข้อ "เมนู" |
| การ์ดราคาย่อยในบทความบริการแต่ละอัน | ราคาเป็น **บรรทัดเดียวใต้เส้น** + ลิงก์ไปตารางเต็ม | ลดการ์ดตามที่ลูกค้าสั่ง · และการ์ดราคาย่อยขัดกับตารางเรตจริงที่อยู่ท้ายหน้า |

### รอบ composition — จังหวะแนวตั้งกับลำดับความสำคัญ ไม่แตะ CI และไม่แตะเนื้อหา

> ลูกค้าสั่ง **"ปรับ layout ให้ดูตั้งใจออกแบบ ไม่ใช่ประกอบจากคอมโพเนนต์สำเร็จรูป"**
> พร้อมกำกับว่า **ไม่ใช่การเปลี่ยน CI และไม่ใช่การ redesign** — สี โลโก้ ฟอนต์ เนื้อหา
> โครงสร้างบริการ คงไว้ทั้งหมด · และมีข้อ **"ห้าม overcorrect"** กำกับไว้ด้วยว่า
> ห้ามกลายเป็น minimal จนขาดข้อมูล หรือกลายเป็น fashion editorial
>
> รอบนี้เริ่มจาก **วัดก่อนแก้** ทุกข้อในตารางล่างมีตัวเลขจากการวัดหน้าจริงรองรับ
> และมีหลายข้อในโจทย์ที่ **วัดแล้วพบว่าผ่านอยู่แล้ว จึงไม่แตะ** (ดูท้ายหัวข้อ)

| ข้อบกพร่องที่วัดได้ | ตอนนี้แก้ด้วย |
|---|---|
| `/services/inspection` มี **11 section ติดกันที่ระยะ 128/128px เป๊ะ** — หน้าทั้งหน้าหายใจเป็นจังหวะเดียว | **`rhythm` scale 4 ระดับ** ใน `ui.tsx` · กติกาคือ **section ที่ติดกันห้ามใช้ระดับเดียวกัน** ตอนนี้หน้านี้ไล่เป็น base→dense→open→dense→open→base→dense→base→dense→open→dense→open |
| **9 section ใช้หัวข้อทรงเดียวกันหมด** (ป้ายเล็ก → หัว 42px ชิดซ้าย → ย่อหน้า) | **`SectionHeading` มี 3 ทรง** — `stack` (เดิม) · `split` (คำโปรยไปอยู่ขวา ใช้กับหัวหน้าเพจ) · `rule` (เส้นคาดใต้ป้าย ใช้ประกาศ "ขึ้นบทใหม่") · **`rule` ใช้ได้หน้าละตัวเดียว** ถ้าใส่หลายที่มันจะกลายเป็นเทมเพลตอีกแบบ |

| `/articles` เป็น **การ์ด 3 ใบเท่ากัน** ทั้งที่ `FeaturedArticle` มีอยู่ในโค้ดมาตลอด — grep แล้ว **ไม่เคยถูกเรียกใช้เลย** | หมวดละ **1 ชิ้นเด่น + ที่เหลือเป็นกริด 2 คอลัมน์** · สองหมวดใช้ `rhythm` คนละระดับ (ตรวจบ้าน `base` / ตกแต่ง `dense`) เพราะหมวดหนึ่งเป็นเนื้อหาหลัก อีกหมวดเป็นส่วนต่อท้าย |

**กฎ "ชิ้นแรกของชุดคือชิ้นนำ"** ใช้ตรงกันทั้ง 3 ที่ (บริการตรวจสอบ · บทความ · บริการตกแต่ง)
โดยยึด **ลำดับในข้อมูลของลูกค้า** ไม่ได้จัดอันดับเอง — ถ้าลูกค้าอยากสลับว่าอะไรเป็นชิ้นนำ
ให้สลับลำดับใน `site.ts` / `articles.ts` ไม่ต้องแก้ layout

**ข้อที่วัดแล้วผ่านอยู่แล้ว จึงไม่แตะ** (ตามข้อ "ห้าม overcorrect"): ความกว้างย่อหน้าสูงสุด 672px
(เกณฑ์ 600–750) · ไม่มีขอบที่ "เกือบตรงแต่ไม่ตรง" ระดับโครงสร้าง (ที่เจอเป็นคู่ไอคอน/ตัวเลขในบรรทัดเดียวกัน)
· ไม่มี horizontal scroll ที่ 390px · แถบ CTA ลอยมี `env(safe-area-inset-bottom)` และทับ element = 0
· รีวิวเป็น 1 ใหญ่ + 2 เล็กอยู่แล้ว · ขั้นตอนการตรวจเป็นไทม์ไลน์ที่วิ่งตาม scroll อยู่แล้ว ไม่ใช่การ์ด 4 ใบ
· รายงานเป็นภาพใหญ่พร้อมหมุดชี้อยู่แล้ว · `TrustBar` เป็นแถบคั่นเส้น ไม่ใช่การ์ด 4 ใบ

**ข้อที่ทำไม่ได้เพราะไม่มีของ** — บันทึกไว้ที่ "สิ่งที่ยังค้าง": ภาพก่อน/หลัง และ FAQ
(ไม่มีข้อมูลจากลูกค้า **ห้ามแต่งขึ้นเอง**) · รูปวิศวกรตัวจริงสำหรับบล็อกใบอนุญาต และรูปเครื่องมือ
สำหรับหัวข้อ "เครื่องมือที่ใช้" (ภาพทุกไฟล์ใน `public/images` ถูกใช้ไปแล้วอย่างน้อยหนึ่งครั้งในหน้านั้น
เอามาใช้ซ้ำรอบที่สามจะอ่านออกทันทีว่าเป็น stock) — สองข้อนี้จึง **เพิ่มน้ำหนักด้วย layout แทน**

### `rhythm` — ระยะแนวตั้งของ section

ประกาศที่ `ui.tsx` · **ห้ามใส่ `py-*` ที่ section โดยตรง** ให้ใช้ token เพื่อให้จังหวะทั้งเว็บคุมได้จากที่เดียว

| token | ค่า | ใช้กับ |
|---|---|---|
| `tight` | `py-10 sm:py-12` | แถบคั่น · สารบัญในหน้า |
| `dense` | `py-14 sm:py-20` | หัวข้อรอง · ส่วนต่อท้าย |
| `base` | `py-20 sm:py-28` | ค่าเริ่มต้นของ section เนื้อหา |
| `open` | `py-24 sm:py-36` | บทหลักของหน้า · แถบพื้นเข้ม |

> **กติกาเดียวที่ห้ามผิด: section ที่อยู่ติดกันห้ามใช้ระดับเดียวกัน**
> จังหวะที่ต้องการคือ แน่น → หายใจ → แน่น → ภาพ → หายใจ ไม่ใช่ระยะเท่ากันทั้งหน้า
> เช็กเร็ว: `[...document.querySelectorAll('section')].map(s=>getComputedStyle(s).paddingTop)`
> ถ้าเห็นค่าเดียวกันซ้อนกันเกินสองตัว แปลว่าหลุดกติกา

### กติกาการวางคอลัมน์ — อ่านก่อนเพิ่ม section ใหม่

รอบเก็บงานเจอข้อผิดพลาดชุดเดียวกันใน 5 section ติดกัน ต้นเหตุเดียวกันหมด คือ
**ลืมว่า grid ยืดลูกทุกตัวให้สูงเท่าแถว (`align-items: stretch`) เสมอ**
พอสองคอลัมน์มีเนื้อหายาวไม่เท่ากัน กล่องจะเท่ากันแต่เนื้อในไม่เท่า แล้วเกิดรูโหว่

| อาการที่เห็น | ต้นเหตุจริง | กติกา |
|---|---|---|
| แผ่นภาพลอยต่ำกว่าหัวข้อครึ่งจอ ไม่มีเส้นไหนตรงกัน | `items-center` บนสองคอลัมน์ที่สูงต่างกัน 253px | **แขวนทุกคอลัมน์จากเส้นบน** (`items-start`) · ที่ว่างท้ายคอลัมน์ (rag) เป็นเรื่องปกติ ที่ว่างกลางคอลัมน์ไม่ใช่ |
| แถบคำบรรยายกรมท่าลอยอยู่ *ใต้* ภาพบนพื้นครีม 6 ใน 9 ใบ | `nth-child(3n+2):mt-12` ดันแถวให้สูงกว่าภาพ 48px แล้ว `absolute bottom-0` ไปเกาะก้นกล่องที่ถูกยืด ไม่ใช่ก้นภาพ | ถ้ามี absolute ยึด `bottom-0` ในกริด **ต้อง `items-start`** ไม่งั้นมันเกาะก้นแถว ไม่ใช่ก้นเนื้อหา |
| ชื่อคนพูดหลุดไปอยู่ก้นกล่อง ห่างจากคำพูด ~100px | `h-full` + `flex-1` บน blockquote | อย่าใช้ `flex-1` / `mt-auto` ดันของท้ายกล่องเพื่อ "ปิดรู" — มันแค่ **ย้าย**ที่ว่างไปอยู่กลางคอลัมน์แทนท้ายคอลัมน์ ซึ่งแย่กว่าเดิม (ตารางราคาเคยใช้ท่านี้แล้วถอดออก ดูหัวข้อ "ตารางราคา") · ถ้ารูใหญ่จริง แปลว่าคอลัมน์นั้นมีของไม่พอ ต้องแก้ที่การแบ่งเนื้อหา ไม่ใช่ที่ระยะ |
| ช่องว่างใต้บทความเด่น 382px โดยมีเส้นคั่นแนวตั้งลากผ่านพอดี | เนื้อหา 275px ในกล่อง 657px | ให้ **ภาพ** เป็นตัวรับความสูงส่วนเกิน อย่าปล่อยว่าง · เส้นคั่นเต็มความสูงคือสิ่งที่ทำให้ช่องโหว่เด่นขึ้นมา |
| บทความเด่นมีภาพ **572×199 เตี้ยกว่าบทความรอง (572×358)** ที่อยู่ข้างล่าง | `FeaturedArticle` เคยเขียนให้ **ยืมความสูงจากคอลัมน์ข้าง ๆ** (`lg:aspect-auto` + `lg:h-full` ในกริด 3 คอลัมน์) พอย้ายมาใช้เดี่ยว ๆ ไม่มีคอลัมน์ข้างมาดัน ภาพเลยยุบ | **คอมโพเนนต์ต้องกำหนดสัดส่วนของตัวเองให้ได้โดยไม่พึ่งเพื่อนบ้าน** · `h-full` ในกริดใช้ได้เฉพาะตอนที่รู้แน่ว่ามีพี่น้องในแถวเดียวกันเป็นตัวกำหนดความสูง — ถ้าคอมโพเนนต์นั้นอาจถูกเรียกใช้เดี่ยว ๆ ให้ตั้ง `aspect-*` ไปเลย |

เช็กเร็วในคอนโซล — หา grid ที่ลูกสูงไม่เท่ากันเกิน 80px:

```js
[...document.querySelectorAll('div,ul,dl')].filter(g=>{
  const cs=getComputedStyle(g); if(cs.display!=='grid') return false;
  if(cs.gridTemplateColumns.split(' ').length<2) return false;
  const h=[...g.children].filter(k=>k.offsetHeight).map(k=>k.getBoundingClientRect().height);
  return h.length>1 && Math.max(...h)-Math.min(...h)>80;
})
```

### ตารางราคา — ทำไมถึงหน้าตาแบบนี้

section นี้แก้มาสองรอบ รอบแรกแก้เรื่องระยะอย่างเดียวแล้วไม่หาย
เพราะปัญหาจริงอยู่ที่ **การแบ่งคอลัมน์** ไม่ใช่ที่ระยะ · บันทึกไว้กันแก้ซ้ำรอบสาม

| ข้อบกพร่องที่วัดได้ | ตอนนี้แก้ด้วย |
|---|---|
| ชื่อบริการอยู่คอลัมน์ซ้าย ราคาของมันอยู่คอลัมน์ขวา คั่นด้วยร่อง 64px — "ตรวจคอนโดก่อนโอน" กับ "฿3,500" ไม่เคยเข้าสายตาพร้อมกัน | ชื่อบริการอยู่ **เหนือตารางเรตของตัวเอง** แต่ละกลุ่มจบในตัว ไม่ต้องกวาดสายตาข้ามร่อง |
| คอลัมน์ซ้ายมีตัวอักษร ~130px ในกล่องที่ grid ยืดเป็น 255px คูณ 3 กลุ่ม → ครึ่ง section เป็นที่ว่าง · `md:mt-auto` รอบแรกแค่ย้ายที่ว่างไปไว้กลางคอลัมน์ | ที่ว่างถูกแทนด้วย **แผงเงื่อนไข `priceIncludes`** ที่ `lg:sticky lg:top-24` — เงื่อนไขค้างอยู่ในสายตาตลอดช่วงที่เลื่อนอ่านราคา |
| "ดูรายละเอียดบริการ" ซ้ำ 3 ครั้ง คู่กับคำโปรยที่ยาวใกล้กันทั้งสามอัน อ่านเป็นย่อหน้าเดียววนซ้ำ | ย่อเป็น "ดูรายละเอียด" + ย้ายขึ้นไปอยู่แถวหัวกลุ่ม (`sm:col-start-2 sm:row-start-1`) ไม่ใช่ท้ายบล็อก |
| ที่ 768px แถวเรตกว้างเต็ม 704px เหลือที่ว่าง ~480px ระหว่างชื่อขนาดกับราคา ตาไล่ไม่ถูกคู่ | **เส้นนำสายตา (leader)** แทนเส้นคั่นแถว — เส้นคั่น *แยก* ของสองฝั่ง เส้นนำ *เชื่อม* · วัดแล้วเส้นยาว 236–420px แล้วแต่ความกว้างจอ |

**ท่าที่ใช้แล้วต้องรู้ที่มา** — สามอย่างนี้ดูแปลกถ้าไม่รู้เหตุผล อย่าเผลอ "แก้ให้เรียบร้อย":

- **`sticky` บนลูกของ grid** — containing block ของมันคือ *grid area* ซึ่งยังสูงเต็มแถวถึงแม้
  `items-start` จะย่อกล่องลงแล้ว · ระยะที่เลื่อนได้ = ความสูงแถว − ความสูงแผง
  ดังนั้น `items-start` ในกริดนี้ทำสองหน้าที่พร้อมกัน (กันรูโหว่ + เปิดระยะให้ sticky วิ่ง)
  **ถอด `items-start` ออกเมื่อไหร่ sticky ตายทันที** โดยไม่มี error อะไรเตือน
- **เส้นนำเป็น `<span>` เปล่าใน `items-baseline`** — baseline ของ block element ที่ไม่มีเนื้อหา
  คือขอบล่างของมันเอง เส้นเลยไปนั่งบน baseline ของข้อความข้าง ๆ พอดีโดยไม่ต้องคำนวณ offset
  (วัดแล้วคลาด 1–2px) · ถ้าใส่เนื้อหาอะไรลงไปในนั้น เส้นจะเลื่อนหลุด baseline ทันที
- **`DrawnRule tone="ink"` ไม่ใช่ `border-t border-ink`** — `border` จริงสั่ง `scaleX` ไม่ได้
  ต้องเป็น element ของตัวเองถึงจะลากเส้นเข้ามาตอนเลื่อนถึงได้ · ทุกคอลัมน์ในกริดนี้
  **เริ่มด้วยเส้น ink เส้นเดียวกัน** เพื่อให้ทั้งสองฝั่งแขวนจากเส้นบนเส้นเดียว
  (กติกา `items-start` ข้างบน — ถ้าฝั่งหนึ่งเริ่มด้วยเส้น อีกฝั่งเริ่มด้วยข้อความ ตาจะจับไม่ได้ว่าตรงกัน)

**เนื้อหาในแผงห้ามเขียนลอย ๆ** — `priceIncludes` ใน `lib/site.ts` มีคอมเมนต์กำกับที่มาของทุกบรรทัด
ว่าดึงมาจาก `whyChooseUs` / `timeline` / `inspectionServices` ข้อไหน · ระยะเวลาสองข้อ
interpolate จาก `timeline` ตรง ๆ ไม่ได้พิมพ์ซ้ำ ตารางราคากับขั้นตอนการทำงานเลยขัดกันเองไม่ได้
**จะเพิ่มข้อใหม่ต้องอ้างที่มาได้แบบเดียวกัน**

**สิ่งที่ brief ขอแต่ไม่ทำ** (ทั้งสองข้อขัดกับกฎ "ห้ามแต่งข้อมูลขึ้นมาเอง" ในตัว brief เอง)

- **ดาว ★★★★★ ในรีวิว** — เว็บนี้ไม่มีระบบให้คะแนนจริงรองรับ ใส่แล้วเป็นการกล่าวอ้างลอย ๆ
  ใช้ `FIELD NOTE 01` แทน ซึ่งให้จังหวะ editorial เหมือนกันโดยไม่อ้างตัวเลขที่ไม่มี
- **เลขรายงานแบบ `DD-2026-0231`** — เลขที่ดูเหมือนจริงอันตรายกว่า placeholder ที่อ่านออก
  ใช้ `DD-XXXX` จนกว่าจะได้รูปแบบจริงจากลูกค้า

**custom cursor** (ข้อ 26 ใน brief ระบุว่า optional) — **ยังไม่ทำ** เพราะบนงานที่ยังใช้ภาพ stock
ทั้งหมด cursor พิเศษจะกลายเป็นลูกเล่นที่เด่นกว่าเนื้อหา · ถ้าจะทำ ต้องปิดบนมือถือและ pointer หยาบ

## หมายเหตุสำหรับคนรับงานต่อ

- **ก่อนเพิ่ม section ใหม่ลงหน้าแรก ให้ถามก่อนว่ามันควรมี URL ของตัวเองไหม** — หน้าแรกถูกรื้อ
  จาก 14 section เหลือ 8 มาแล้วรอบหนึ่ง ถ้าปล่อยให้โตกลับไปเรื่อย ๆ จะกลายเป็น landing page เหมือนเดิม
  · เกณฑ์ที่ใช้: ถ้าหัวข้อนั้นมีคนค้นหาโดยตรงได้ (ราคา / ขั้นตอน / ผลงาน) มันควรเป็นหน้า
  ไม่ใช่ section · ดูหัวข้อ "สถาปัตยกรรมข้อมูล"
- **`PricingTable` เป็นตารางราคาชุดเดียวของเว็บ** — อยู่ใน `sections.tsx` ไม่ใช่ในไฟล์ route
  ลิงก์ "ดูเรตทุกขนาด" ในบทความบริการแต่ละอันเป็น anchor ในหน้าเดียวกัน (`#pricing`)
  ไม่ใช่ลิงก์ข้ามหน้า · ถ้าจะเอาตารางไปใช้อีกหน้า ต้องย้าย `id` ไม่ใช่ก๊อปมาร์กอัป
- **ลิงก์ที่หน้าตาเป็น "ลิงก์กด" ต้องใช้ `GhostLink` ไม่ใช่ `<a className="underline">`** —
  `GhostLink` มี `min-h-[44px]` ติดมาแล้ว · เคยใส่เป็น `<a>` ธรรมดาแล้วได้พื้นที่กด 75.8×24.0px
  ซึ่งตกเกณฑ์ touch target ทั้งสามจุดในหน้าเดียว · ลิงก์ที่แทรก**กลางประโยค**ไม่เข้าข่ายนี้
  (เป็น inline prose) แต่ลิงก์ที่ยืนเดี่ยวท้ายบล็อกเข้าข่ายเสมอ ·
  `className` ของ `GhostLink` ใช้จัดตำแหน่งเท่านั้น (margin / grid placement / order) ห้ามใส่สีหรือขนาด
- **เมนูมือถือเรนเดอร์อยู่นอก `<header>`** — เดิมจำเป็นเพราะ header ใช้ `backdrop-blur` ซึ่งทำให้มันกลายเป็น containing block ของ `position: fixed` ลูก (panel ยุบเหลือ 0px) · รอบ editorial ถอด blur ออกแล้ว ข้อจำกัดนี้จึงหมดไป แต่ยังวางไว้นอกเหมือนเดิมเพราะไม่มีเหตุผลต้องย้าย ถ้าจะเอา blur กลับมาต้องอย่าย้าย panel เข้าไปข้างใน
- **อย่าส่ง variant ของปุ่มผ่าน `className`** — Tailwind ตัดสิน utility ที่ชนกันด้วยลำดับใน stylesheet ไม่ใช่ลำดับใน class attribute เคยทำให้ปุ่มบนพื้นเข้มเป็นตัวหนังสือขาวบนพื้นขาว ใช้ prop (`<BookCta tone="onDark" />`) แทน
- **อย่าส่ง `absolute` เข้าไปใน `MockImage`** — root ของมันเป็น `relative` อยู่แล้ว และ Tailwind เรียง `relative` ไว้**หลัง** `absolute` ใน stylesheet ที่ generate ออกมา ตัวที่ส่งเข้าไปจะแพ้เงียบ ๆ เสมอ · ถ้าต้องวางภาพแบบลอย ให้ห่อด้วย `<div>` ที่ absolute แล้วให้ภาพเป็น `h-full w-full` (โดนมาแล้ว 2 จุด: พื้นหลัง `ContactCta` กับภาพซ้อนใน `ReportShowcase` — ตัวหลังถอดออกแล้วตอนแก้คอลัมน์ เหลือ `ContactCta` ที่ยังใช้ท่านี้อยู่จุดเดียว)
- **`last:` ของ Tailwind = last-child ของ parent จริง ไม่ใช่ "ตัวสุดท้ายใน loop"** — เส้นเชื่อมขั้นตอนเคยเขียนเป็น `last:hidden` บน `<span>` ที่เป็นลูก**ตัวแรก**ของ `<li>` เงื่อนไขจึงไม่เคยเป็นจริง และขั้นที่ 5 ลากเส้นหลุดออกนอกจอ · ตอนนี้ตัดด้วยเงื่อนไขใน JSX แทน
- **แถวใน `FeaturedServices` ต้องเป็น `variant="fade"` เท่านั้น** — element ที่มี `transform` จะกลายเป็น containing block ของลูกที่ `position: absolute` ถ้าเปลี่ยนเป็นท่าที่มี transform ภาพคอลัมน์ขวาจะไปอิง `<li>` แทน `<ul>` แล้วหลุดตำแหน่งทันที
- **อย่าเอา `setTimeout` กันเหนียวใน `<Counter>` ออก** — `requestAnimationFrame` หยุดเดินเมื่อแท็บถูกซ่อน ตัวเลขจะค้างที่ค่าผิดถาวร (เจอจริง: ค้างที่ `18+` ทั้งที่ค่าจริง `1,500+`) · เหตุผลเดียวกันนี้ทำให้ screenshot ตอน preview ออกมาขาวเปล่าถ้าแท็บไม่ได้อยู่หน้าสุด — เช็ก `document.visibilityState` ก่อนสงสัยว่าโค้ดพัง
- **ป้ายที่ถ่าง `letter-spacing` ห้ามใส่ข้อความไทย** — ดูกล่องเตือนในหัวข้อ Typography มีวิธีเช็กทั้งเว็บด้วย console
- **พื้นหลังของ `ContactCta` ต้องเป็นภาพห้องว่าง ไม่ใช่ภาพคน** — ใบหน้าที่จางอยู่หลังหัวข้อดึงสายตาแย่งข้อความ และทำให้ลูมิแนนซ์ไม่สม่ำเสมอจนคุมคอนทราสต์ไม่ได้
- **เวลาเปลี่ยนชุดสี ให้ไล่ `grep` ทีละ token แล้วนับผลลัพธ์เทียบกับที่คาดไว้** — รอบกรมท่า+ทองใช้ `perl -pi` แทนทั้งไฟล์ แล้วมีกฎหนึ่งที่มี **ข้อความไทย** อยู่ใน pattern ซึ่ง match ไม่ติดเงียบ ๆ (คำเน้นใน `h1` ค้างเป็นสีเดิมอยู่จุดเดียว) · หลัง bulk replace ทุกครั้งต้อง `grep` token เก่าให้เหลือศูนย์ และ `grep` token ใหม่นับจำนวนต่อไฟล์
- **ตัวเลขทุกจุดในเว็บเป็นสีทอง** (ราคา เลขลำดับขั้นตอน ตัวเลขสถิติ เลขใบอนุญาต `404`) — `TrustBar` (เดิมชื่อ `Stats`) เคยไม่ได้ใส่คลาสสีเลยจึงตกไปเป็นกรมท่าตามที่ inherit มา ถ้าเพิ่มบล็อกตัวเลขใหม่ต้องใส่สีเอง: ≥24px ใช้ `text-gold-500` · เล็กกว่านั้นใช้ `text-gold-700`
- **`MockImage` มี prop `zoom`** (ขยาย 1.04 ตอน hover) — ต้องให้ตัวครอบเป็น `group` ถึงจะทำงาน · ตั้ง 700ms ช้ากว่าไมโครอินเทอแรกชันทั่วไป**โดยตั้งใจ** ภาพใหญ่ที่ซูมเร็วอ่านเป็นโฆษณา · ใช้กับภาพที่กดได้เท่านั้น อย่าใส่กับภาพประกอบเฉย ๆ เพราะ hover ที่ไม่พาไปไหนคือสัญญาที่ทำไม่ได้
- **ไล่เฉดทับภาพในแกลเลอรีใช้ `ink-deep` ไม่ใช่ดำ** — ดำบนภาพโทนอุ่นจะออกเทาสกปรก · ช่วงล่างต้องทึบเกือบเต็มเพื่อคุมคอนทราสต์ตัวหนังสือขาวไม่ว่าภาพจะสว่างแค่ไหน (ภาพจริงที่ลูกค้าส่งมาคุมความสว่างไม่ได้)
- **`window.scrollTo()` ในเครื่องมือทดสอบอาจไม่ยิง event `scroll`** — ตอนตรวจแถบเมนูที่หดตามการเลื่อน ถ้าวัดแล้วความสูงไม่เปลี่ยน ให้ `dispatchEvent(new Event('scroll'))` ตามหลัง ก่อนจะสรุปว่าเป็นบั๊ก (เสียเวลาไล่อยู่พักหนึ่ง) · `html` ตั้ง `scroll-behavior: smooth` ด้วย เวลา scroll ด้วยสคริปต์ต้องส่ง `behavior: 'instant'`
